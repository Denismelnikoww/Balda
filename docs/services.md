## 1. `identity.credentials`

| Поле                            | Содержание                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ответственность**             | Управляет аккаунтами владельцев и их связками с внешними провайдерами: регистрация, OAuth-подключение, выдача/хранение/отзыв мандатов. Реализует бизнес-возможность «безопасный доступ от имени пользователя».                                                                                                                                    |
| **Владеет данными**             | `Owner`, `Connection`, `Mandate` (токены, scopes, срок жизни), `Revocation`. Единственный источник истины по мандатам и связкам.                                                                                                                                                                                                                  |
| **Предоставляет**               | **API:** <br>`GET /owners/{id}`<br>`GET /owners/{id}/connections`<br>`POST /connections/{id}/mandate:resolve` (выдать действующий мандат для исполнения), <br>`POST /connections` (OAuth-callback), <br>`DELETE /connections/{id}`. <br>**События:** `OwnerRegistered`, `ProviderConnected`, `MandateIssued`, `MandateRevoked`, `MandateExpired`. |
| **Зависит от**                  | Внешние OAuth-провайдеры - синхронно при OAuth-флоу. Внутренних зависимостей нет.                                                                                                                                                                                                                                                                 |
| **Нефункциональные требования** | Нагрузка низкая/средняя (OAuth-флоу редкий, resolve мандата - на каждое действие Delivery). Критичность **высокая** (без мандата ничего не исполняется). Задержка resolve - **< 50 мс p99** (в горячем пути Delivery), кэш мандатов на стороне Delivery.                                                                                          |
| **Обоснование границы**         | (1) Свой язык и инварианты: «мандат», «связка», «отзыв» - не пересекаются с планированием/исполнением; <br>(2) максимальный риск-профиль (секреты, OAuth) требует изоляции доступа;                                                                                                                                                               |

## 2. `behavior.profile`

| Поле                            | Содержание                                                                                                                                                                                                                                 |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Ответственность**             | Строит и хранит модель типичного поведения владельца (рабочие часы, частота, стиль коммитов/сообщений) и отдаёт её как ожидания/паттерны для планирования. Реализует возможность «активность похожа на настоящую».                         |
| **Владеет данными**             | `BehaviorProfile`, `ActivityPattern`, `Expectation`, `Style`. Единственный источник истины по профилю и паттернам.                                                                                                                         |
| **Предоставляет**               | **API:** `GET /owners/{id}/profile`, `GET /owners/{id}/patterns?window=...`, `PUT /owners/{id}/profile`. <br>**События:** `BehaviorProfileCreated`, `BehaviorProfileUpdated`, `ActivityPatternRecorded`, `ProfileDrifted`.                 |
| **Зависит от**                  | Подписан на `ActionSucceeded` / `ActionFailed` / `ActionCompensated` от `delivery.integrations` (источник фактов для паттернов) и на `PlanStarted`/`PlanCancelled` от `campaign.plan` (контекст наблюдений). Синхронно никого не вызывает. |
| **Нефункциональные требования** | Нагрузка средняя (чтение профиля при построении плана, запись паттернов по событиям). Критичность **средняя**. Задержка чтения **< 100 мс p99**.                                                                                           |
| **Обоснование границы**         | (1) Своя модель «наблюдений/ожиданий», отличная от «намерений» Plan; <br>(2) обучается/дрейфует - свой жизненный цикл; <br>(3) другие контексты его только _читают_, не владеют им.                                                        |

## 3. `campaign.plan` - **ядро**

| Поле                            | Содержание                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ответственность**             | Принимает намерение пользователя, строит связный план активности с учётом профиля и политик правдоподобия, оркестрирует исполнение шагов через сагу, управляет жизненным циклом плана (запуск/пауза/отмена).                                                                                                                                                                                                                                                                                                     |
| **Владеет данными**             | `Intent`, `ActivityPlan`, `PlanStep`, `Policy`, состояние саги (`SagaState`). Единственный источник истины по планам и их шагам.                                                                                                                                                                                                                                                                                                                                                                                 |
| **Предоставляет**               | **API:** `POST /intents`, `POST /plans` (сгенерировать), `GET /plans/{id}`, `PATCH /plans/{id}` (скорректировать), `POST /plans/{id}:start\|pause\|cancel`. <br>**События:** `IntentSubmitted`, `ActivityPlanCreated`, `ActivityPlanAdjusted`, `PlanStarted`, `PlanPaused`, `PlanCancelled`, `PlanStepScheduled`, `ActionRequested` (команда в Delivery). **Подписки (вход):** `ActionSucceeded`, `ActionFailed`, `ActionCompensated`, `BehaviorProfileUpdated`, `SubscriptionActivated`, `SubscriptionExpired`. |
| **Зависит от**                  | `identity.credentials` (синхронно: проверить наличие действующего мандата перед планированием/исполнением), `behavior.profile` (синхронно: профиль + подписка на `BehaviorProfileUpdated`), `delivery.integrations` (асинхронно: команды/события, сага), `billing.notification` (подписка на статус подписки/лимиты).                                                                                                                                                                                            |
| **Нефункциональные требования** | Нагрузка: пики при массовом планировании (вечер воскресенья - «на выходные»), запись шагов и таймеров. Критичность **высокая** (ядро продукта). Задержка API планирования **< 500 мс p95**. Таймеры шагов - точность до минут.                                                                                                                                                                                                                                                                                   |
| **Обоснование границы**         | (1) Ядро домена: уникальный язык «намерение/план/шаг/политика/сага», свои инварианты связности; <br>(2) владеет распределённой согласованностью (сага) - её нельзя размазать; <br>(3) максимальная бизнес-ценность и частота изменений правил планирования.                                                                                                                                                                                                                                                      |

## 4. `delivery.integrations`

| Поле                            | Содержание                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ответственность**             | Исполняет единичные действия во внешних сервисах через ACL-адаптеры: вызовы API, retry, rate limiting, идемпотентность, компенсации. Реализует возможность «действие реально произошло».                                                                                                                                                                                              |
| **Владеет данными**             | `Action` (actionId, тип, статус), `IdempotencyKey`, `ExecutionAttempt`, `ProviderRateLimit`, `ExternalRef`. Единственный источник истины по фактам исполнения и внешним ссылкам.                                                                                                                                                                                                      |
| **Предоставляет**               | **API (admin/debug):** `GET /actions/{id}`, `GET /actions?planId=...`. **События:** `ActionSucceeded` (с `externalRef`), `ActionFailed` (с `errorCode`, `retryable`), `ActionRetried`, `ActionCompensated`, `CommitCreated`, `MessageSent`, `StatusChanged`, `TicketUpdated`, `EmailSent`, `ProviderRateLimitReached`. <br>**Подписки (вход):** `ActionRequested` от `campaign.plan`. |
| **Зависит от**                  | `identity.credentials` (синхро\но: resolve мандата в момент исполнения - не получает токены в событиях), внешние API (Git-провайдер, WK Teams, Ledmine, SMTP) - sync. Подписан на `ActionRequested`.                                                                                                                                                                                  |
| **Нефункциональные требования** | Нагрузка: пропорциональна числу шагов планов, I/O-bound, зависит от rate limits провайдеров. Критичность **высокая** (без исполнения нет продукта), но изолируемая (падение одного адаптера не роняет остальные). Задержка одного действия - секунды (внешний API); внутренняя обработка **< 100 мс**. Гарантия **at-least-once** + идемпотентность по `actionId`.                    |
| **Обоснование границы**         | (1) ACL под каждый провайдер - своя модель «действия» и своя механика retry/rate limit; <br>(2) Delivery не знает про план и порядок шагов (только `actionId` + `correlationId` для трассировки); <br>(3) высокий риск/доступ к чужим API - изоляция; <br>(4) переиспользуем: может дёргаться не только из Plan (например, ручное действие).                                          |

## 5. `billing.notification`

| Поле                            | Содержание                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ответственность**             | Управляет подпиской и тарифными лимитами, проводит оплату через платёжный шлюз.                                                                                                                                                                                                                                                                                         |
| **Владеет данными**             | `Subscription`, `Tariff`, `Payment`. Единственный источник истины по подписке, платежам.                                                                                                                                                                                                                                                                                |
| **Предоставляет**               | **Sync API:** `GET /owners/{id}/subscription`, `POST /subscriptions` (оформить), `POST /payments` (инициировать). <br>**События:** `SubscriptionActivated`, `SubscriptionExpired`, `PaymentSucceeded`, `PaymentFailed`, `NotificationSent`. <br>**Подписки (вход):** `OwnerRegistered`, `MandateRevoked`, `ActionFailed` (для уведомлений), `ProviderRateLimitReached`. |
| **Зависит от**                  | Платёжный шлюз (синхрнон), почтовый провайдер SMTP (синхрон) - внешние. Подписан на события `identity.credentials`, `delivery.integrations` для триггера уведомлений.                                                                                                                                                                                                   |
| **Нефункциональные требования** | Нагрузка низкая (оплата/уведомления редки). Критичность **средняя** (деградация → нет новых подписок/уведомлений, но генерация работает). Задержка - не критична (секунды). Идемпотентность платежей по `paymentId`.                                                                                                                                                    |
| **Обоснование границы**         | (1) Свой домен «подписка/платёж/тариф/уведомление» - не пересекается с активностью; <br>(2) интеграция с деньгами требует изоляции и своего аудита; <br>(3) меняется независимо (тарифы, шлюзы, шаблоны писем); <br>(4) Notification - естественный подписчик на события, но владеет только фактом отправки.                                                            |
